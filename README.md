# IPTV 直播源自动检测与分类

> 基于 GitHub Actions 的 IPTV 直播源自动检测、源龄分析、多维度分类工具。  
> 支持并发检测、防盗链识别、真实更新时间获取、持久化缓存。

---

## ✨ 核心特性

| 特性 | 说明 |
|------|------|
| 🔄 自动触发 | `live.txt` / `check_iptv.py` / `check.yml` 任一变动即自动运行 |
| ⚡ 高效检测 | 多线程并发（默认10线程），HEAD→GET 降级，超时20s |
| 🛡️ 防盗链识别 | 403 源区分：GitHub限流(保留) / 网页防盗链(保留) / 私人CDN(标记失效) |
| 📅 智能源龄 | GitHub/Gitee API → JsDelivr → Last-Modified → URL日期 → git log → 未知 |
| 🏷️ Date头降级 | HTTP `Date` 仅标记"今日活跃"，**不污染更新分档**，避免误判 |
| 💾 持久缓存 | `source_age_cache.json` 记录检测结果，逐次积累，未知比例递减 |
| 📊 多维度输出 | 按可用性、响应时间、源龄四档、僵尸源自动分类 |

---

## 📂 输出文件

| 文件 | 说明 |
|------|------|
| `live_ok.txt` | ✅ 可用源（按源龄四档+字母序排列） |
| `live_ok.m3u` | 📺 可用源播放列表（按响应时间排序） |
| `live_fail.txt` | ❌ 真失效源（连通失败） |
| `live_week.txt` | 🆕 一周内真实更新且可用 |
| `live_month.txt` | 📅 一个月内更新 |
| `live_3month.txt` | 📆 三个月内更新 |
| `live_old.txt` | 🧓 超三个月全部源 |
| `live_stale.txt` | 🧟 超90天且不通的僵尸源 |
| `live_report.csv` | 📋 9列详细报告（生成时间/更新日期/状态码/响应ms/状态/类型/源龄/分档/备注/网址） |
| `source_age_cache.json` | 🗄️ 源龄检测缓存（自动读写，加速后续运行） |

### 源龄分档规则

| 分档 | 条件 | 说明 |
|------|------|------|
| 🆕 一周内 | ≤7天 且可用 | 近期活跃源 |
| 📅 一个月内 | ≤30天 | 较新源 |
| 📆 三个月内 | ≤90天 | 正常维护源 |
| 🧓 超三个月 | >90天 | 老源（仍存活） |
| ❓ 未知 | 无法获取更新时间 | 含仅返回Date头的403防盗链源 |

## ⚙️ 工作流程

```
┌─────────────────────────────────────────────────────────────┐
│  push / workflow_dispatch                                    │
│  (live.txt | check_iptv.py | check.yml)                      │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  1. 读取 live.txt，去重                                       │
│  2. 并发检测每个 URL（HEAD→GET 降级，超时20s）                  │
│  3. 判定可用性（200/206/301/302 + 403特定场景）                 │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  4. 源龄检测（逐 URL）：                                      │
│     ├─ GitHub/Gitee API → 真实提交日期                        │
│     ├─ JsDelivr CDN → 发布时间                               │
│     ├─ HEAD Last-Modified → 文件修改时间                      │
│     ├─ URL 内日期特征 → 提取                                  │
│     ├─ 本地 git log → 本仓库文件                              │
│     └─ HEAD Date → 仅标记"今日活跃"，不计入分档 ⚠️             │
│  5. 缓存结果 → source_age_cache.json                          │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  6. 按规则生成输出文件                                        │
│  7. git add -f 输出文件 + 缓存 → commit → push                │
└─────────────────────────────────────────────────────────────┘
```

## 🚀 快速使用

### 1. Fork / Clone 仓库

```bash
git clone https://github.com/你的用户名/你的仓库名.git
cd 你的仓库名
```

### 2. 编辑直播源列表

在 `live.txt` 中每行放一个 URL：

```text
https://gitee.com/xxx/raw/main/live/TV
https://live.example.com/tv.m3u
https://raw.githubusercontent.com/xxx/yyy/main/list.m3u
```

### 3. 推送触发

```bash
git add live.txt
git commit -m "更新源列表"
git push
```

或前往 GitHub → **Actions** → **IPTV Check** → **Run workflow** 手动触发。

### 4. 查看结果

- Actions 运行日志显示统计摘要
- 输出文件随 commit 自动推送至仓库
- 下载 `live_ok.m3u` 即可导入播放器

## 🔧 配置参数

在 `check.yml` 或手动触发时可调整：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--threads` | 10 | 并发检测线程数 |
| `--timeout` | 20 | 单次请求超时（秒） |
| 源龄分档阈值 | 7/30/90天 | 修改 `check_iptv.py` 中 `RECENT_DAYS` 等常量 |

## 📊 如何验证更新时间准确性？

### 方法一：查看 CSV 报告

`live_report.csv` 的**备注列**会标注来源：

| 备注 | 含义 |
|------|------|
| `🆕7天内更新` | 真实更新（API/Last-Modified） |
| `仅今日活跃(Date头)` | 仅连通，无真实更新时间 |
| `源龄未知` | 完全无法获取 |

### 方法二：命令行验证

```bash
# 查看响应头
curl -I "https://目标URL"

# 对比 Last-Modified（真实）vs Date（仅活跃）
```

### 方法三：查看缓存

```bash
cat source_age_cache.json | python -m json.tool
```

缓存中 `"active_today": true` 的条目即为仅 Date 头标记的源。

## ⚠️ 注意事项

1. **GitHub API 限流**：无 Token 限制 60次/小时，缓存机制可缓解
2. **403 防盗链源**：连通但需特定 Referer/UA 才能播放，分档归入"未知"
3. **防递归触发**：输出文件变更不触发工作流（仅监听3个核心文件）
4. **缓存积累**：首次运行未知较多，后续逐次下降
5. **时区**：全部使用北京时间 (Asia/Shanghai)
